## Как работает подготовка

1. Агент готовит и подписывает APK обычной версии прежним ключом.
2. Владелец разрешает агенту подготовку выпуска; агент создаёт черновик через GitHub Actions.
3. Агент локально создаёт одноразовую пару RSA и меняет только публичный `checks/upload-request.json`.
4. Задание `Verify direct draft APK upload` создаёт временный служебный доступ только к этому репозиторию
   с правом `contents:write`. В публичный файл попадает только зашифрованный контейнер.
5. Агент расшифровывает его локально, не выводя секрет в чат или журнал, и загружает APK напрямую в Releases.
6. Задание независимо скачивает APK и JSON, проверяет Android-подпись, пакет, версию, размеры и SHA-256.
7. Задание удаляет файл временного сеанса и завершается; временный доступ перестаёт действовать.
8. Агент удаляет локальный одноразовый закрытый ключ. Постоянный токен владельца не требуется.
9. Для настоящего выпуска владелец сначала проверяет APK и затем сам нажимает **Publish release**.

Зашифрованный контейнер использует RSA-OAEP-SHA256 для ключей, AES-256-CBC и HMAC-SHA256
с проверкой подлинности до расшифрования. Закрытый ключ остаётся только в среде сборки.
Ключ подписи Android, его пароль и какие-либо постоянные секреты не загружаются в этот репозиторий.

## Продолжение для следующего агента

Проверенный контур сейчас настроен на **тестовый** черновик.
Основной сценарий: `.github/workflows/direct-draft-upload.yml`.
Начальное создание черновика отдельно проверено сценарием `check-release-upload.yml`.

Локальные утилиты:
- `tools/prepare_upload_request.py` — создаёт одноразовый ключ и публичный запрос, считает размер и SHA-256;
- `tools/direct_upload_client.py` — загружает подписанный APK и JSON через временный доступ.

Рабочая папка должна содержать `tools`, `checks` и игнорируемую `.release-upload-private`.
Пример подготовки выполняет агент, а не пользователь:

```bash
python3 tools/prepare_upload_request.py \
  --apk /absolute/path/SmartVoice-TJ36.apk \
  --version-name 5.2.28-TJ --version-code 4144 \
  --release-id 424314799
```

Затем агент загружает `checks/upload-request.json` в main через подключение GitHub.
Нужно дождаться файла `checks/upload-session.json` с тем же requestId и сохранить его целиком
в локальную `.release-upload-private/direct/session.json`.
Затем выполняется `python3 tools/direct_upload_client.py`.
Никогда не печатать или вставлять в чат расшифрованный служебный доступ, закрытые ключи и пароли.
Финальный успех проверяется по завершению GitHub Actions и `checks/upload-check-result.json`.

Для настоящего обновления после отдельного согласования:
- добавить в приложение проверку обновлений и переключатель;
- собрать APK с большим versionCode, тем же пакетом и прежней подписью;
- создать отдельный черновик новой версии;
- заменить тестовые признаки JSON и выпуска на признаки обычного стабильного выпуска;
- сохранить окончательную публикацию за владельцем;
- проверить, что обычная версия не получает Full APK.

Не возвращаться к передаче большого APK через десятки base64-вызовов подключения:
она оказалась медленной и упиралась в лимит автоматической проверки.
Прямая загрузка большого файла проверена успешно.
